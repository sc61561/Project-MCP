# Project MCP macOS 启动器设计草案

日期：2026-10-30。状态：仅规划，尚未批准实施；本轮不安装依赖、不修改运行代码、不打包、不提交或发布。

## 已确认的目标

用户选择 macOS 软件：双击打开，选择项目文件夹后一键启动。目标是消除每次使用时复制终端命令、手动配置 Python 和重填连接参数的步骤。

用户已明确 UI 方向：**毛玻璃极简风格，不要多余的二级文字介绍，只保留核心内容**。这是确定约束，不是待选风格。

现有 Python + FastMCP 2.x Server 已验证可用，保持且仅保持 `list_files`、`read_file`、`search_files` 三个只读工具。512 KiB 结果保护、分页、1 MiB 文件限制和根目录/符号链接检查继续有效。

以下首版范围和技术细节是建议方案，留待审阅，不视为用户已经逐项确认。

## 方案比较与建议

| 方案 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| SwiftUI 原生窗口 + 内置 Python Server/隧道运行时 | 系统文件夹选择器、钥匙串、原生进程与窗口体验；用户不用安装 Python | 需维护 Swift 构建和 Python 冻结打包；需要正式签名公证 | 推荐，符合用户选择的双击软件 |
| Python GUI + 冻结打包 | GUI 和 Server 使用同一语言 | GUI 依赖和打包适配，系统集成体验较弱 | 备选，暂不选 |
| CLI 或 Codex 插件 | 初始交付较轻，便于开发者使用 | CLI 保留终端步骤；Codex 插件不等于 ChatGPT 网页本地文件接入 | 用户本次未选择 |

首版建议：macOS 13+、Apple Silicon arm64，SwiftUI 窗口；Python 3.12 + 已验证的 FastMCP 2.14.7 由 PyInstaller onedir 冻结；随应用附带验证过的 tunnel-client。Intel、Windows 和 Linux 不属于首版验收范围。

## 用户流程和首版功能

1. 下载 ZIP，解压，将 `Project MCP.app` 放入应用程序目录并打开。
2. 首次配置 API Key、Tunnel ID、组织 ID；提供官方设置入口。应用不代替用户创建或授权 OpenAI 隧道。
3. 使用系统目录选择器选择一个目标项目；主窗口显示项目名，完整路径可按需查看，后续记住该选择。
4. 点击“启动”，窗口显示准备、连接检查和本地就绪状态。
5. 第一次使用时，在 ChatGPT 添加/授权对应 Tunnel；以后启用现有插件即可。
6. 点击“停止”终止本应用拥有的隧道与 Server。切换项目需先停止再启动。

主窗口只包含：小尺寸应用标题、设置图标、项目选择行、一个状态标识和一个启动/停止主按钮。三个连接字段、“ChatGPT”入口、诊断日志统一收进设置 sheet，默认不在主窗口展开。首版只保存一个当前配置，不做多项目配置管理。

API Key 可选择“记住”：默认不选；未选时仅在本次应用会话内使用，选中时保存到 macOS Keychain。非敏感配置保存到应用自己的 UserDefaults，不写入目标项目，也不把 `.env` 作为 GUI 的运行前提。

不自动开机启动，不自动重连或升级，不做状态栏独立驻留、不自动注册 ChatGPT 插件、不增加 Web UI 或 MCP 工具。

## 已确定的 UI 风格与信息层级

- **材质**：使用 macOS 原生半透明模糊材质，配合极轻描边和柔和阴影；保持轻薄、克制，避免多层玻璃卡片、厚重投影和装饰性高光。
- **布局**：紧凑单窗口、单列、留白明确。无侧边栏、营销头图、统计卡片、功能介绍区或大面积装饰渐变；窗口尺寸以核心控件不拥挤为准，不为介绍文字扩大窗口。
- **色彩与字体**：系统字体、少量字重层级、中性色为主；仅状态和主操作使用少量强调色，不用大面积霓虹、彩色光斑或图标堆砌。
- **主界面文字**：保留 `Project MCP`、`选择项目`/项目名、`未启动`/`启动中`/`本地就绪`/`停止中`/`启动失败`、`启动`/`停止`。不显示副标题、按钮下说明、字段下 helper text、功能口号、重复提示或技术参数。
- **项目路径**：主窗口以项目名和文件夹图标显示；完整路径在 hover 或点击项目行时查看，并提供给辅助功能，不额外常驻一行小字。选择器标题为 `选择项目`。
- **设置 sheet**：只保留 `API Key`、`Tunnel ID`、`组织 ID` 三个必要标签与输入框，`记住密钥` 开关、`保存`、`ChatGPT`/官方设置入口；不附每个字段的介绍段落。缺配置时首次自动进入设置，不增加欢迎页或教程轮播。
- **诊断**：放在设置中的按需展开项；正常状态不展示原始日志。错误时仅显示一句具体原因和必要动作，例如 `密钥无效` + `打开设置`，详细原因在诊断中查看，不重复堆叠错误、解释和提示。
- **必要帮助**：首次 ChatGPT 连接步骤、保持电脑唤醒等运行条件放入按需打开的帮助内容和文档，不作为主界面常驻二级介绍。
- **交互**：动画仅用于状态/控件切换，不做背景呼吸、炫光或连续装饰动效。切换状态时主按钮位置不跳动。
- **可访问性**：遵循系统浅色/深色模式；开启减少透明度时切换为可读的不透明背景，开启减少动态效果时减少过渡。图标按钮保留 tooltip 和 accessibility label；状态不能只靠颜色表达。

风格要求针对产品界面；必要的设计、测试和使用文档保留完整信息，不用“极简”省略错误处理或安全语义。

## 启动和关闭语义

- 不启动时不读取目标项目内容；目录选择只验证路径存在、是目录并可访问。
- 初始进程环境由应用建立，设置 `PROJECT_ROOT` 和隧道所需变量；不依赖终端 PATH、Anaconda、用户 shell 初始化或旧 Codex 绝对路径。
- 直接启动应用内的 tunnel-client，不调用 `/bin/sh -c`、不拼接 shell 命令。
- 冻结 Server 放在只读 bundle 的 `Contents/Resources/server/`，工作目录固定为该目录。隧道的 STDIO 命令固定为 `command=./project-mcp-server,channel=main`；用户项目路径仅通过环境变量传递，不进入命令字符串。
- tunnel-client 放在 `Contents/Resources/runtime/`，通过绝对 executable URL 启动；PyInstaller 的 `_internal` 等支持文件和相对目录结构完整保留。
- UI 通过专用控制管道连接一个轻量 Swift supervisor；由 supervisor 启动独立子进程组并等待回收。只有 supervisor 可以停止这一组；禁止按名称杀死全机 tunnel-client/Python，禁止停止用户现有的终端连接。
- 同一 Tunnel/channel 不应被多个项目实例同时使用。首版在本机发现同一用户已有其他可识别的 tunnel-client 进程时，保守拒绝启动并提示用户自行停止旧客户端；不采集进程环境、不显示命令参数、不自动结束它们。本应用自身通过单实例锁防重复运行。其他机器的客户端无法由本机证明不存在，首次引导要求使用本应用专用 Tunnel，并说明不要与另一台机器共用该 Tunnel。
- 重复点击启动被禁用。健康检查在 loopback 随机端口监听，使用每次运行独有的临时 health URL 文件发现，避免与现有 8080 客户端冲突。
- 当前本地 runtime 的 `run --help` 已确认有 `--health.listen-addr` 和 `--health.url-file`。实施时锁定具备这两个能力的 runtime 并实测健康文件格式；不对缺少这些能力的版本静默退回固定端口。
- 启动前对冻结 Server 做一次独立的 MCP initialize/ping/tools-list 预检，不读项目内容；通过后退出预检进程，再让 Tunnel 启动正式 Server。只有预检通过、正式进程存活、对应健康接口返回 ready 时才显示“本地就绪”。首次连接帮助中说明应在 ChatGPT 调用文件工具验证，不把 readiness 等同于端到端认证成功，也不在主窗口常驻解释。
- 网络断开、进程退出或鉴权错误时显示中文故障提示和可复制的脱敏摘要；首版允许手动重试，不做无限自动重启。
- 启动检查超时为 30 秒；超时后进入错误状态，清理本次进程组。停止先发 SIGTERM，等待最多 5 秒，再对仍属于本次运行的进程组发 SIGKILL，并回收子进程。
- 关闭主窗口/退出应用即停止本应用的连接；运行中退出需提示并允许取消。最小化窗口不停止连接。GUI 崩溃或被强制退出时，supervisor 通过控制管道 EOF 检测并停止自己的子进程组；必须保证子进程不继承管道写端，以免 EOF 检测失效。
- Supervisor 正常收到终止信号时也清理其子进程组；supervisor 自身被 SIGKILL 等不可捕获事件不是可保证的优雅退出场景，不宣称全机任何强杀都无残留。帮助内容说明电脑需保持联网、唤醒。

## 配置、日志和凭据

- Bundle ID 建议为 `com.sc61561.project-mcp`，升级时保持一致；Keychain service 使用该 ID，account 固定为 `control-plane-api-key`。
- 开启“记住”且保存失败时显示错误，禁止静默退回到明文文件；关闭“记住”时移除本应用保存的 Key，但不修改其他凭据。
- 健康 URL、PID 等运行文件保存在应用独占的本次临时目录；应用退出后仅清理该目录。
- 首版日志仅在内存中保留最新 200 行，每行最多 2048 字符。复制诊断前移除 API Key、Authorization 和 token 值，不默认导出用户完整路径或项目内容。
- 不启用 tunnel-client 的 HTTP raw unsafe 日志，不打包任何 `.env`、用户 Key、组织/Tunnel 的真实账号值或项目内容。
- GUI 保存自己的配置、启动子进程属于桌面管理功能；MCP Server 本身的三个工具继续保持只读，没有写入或进程管理接口。
- 首版通过 Developer ID 直接分发，不进入 Mac App Store，不开启 App Sandbox；目录访问仍受 macOS 系统隐私权限约束，权限拒绝需明确提示。

## 运行时和打包策略

建议先用干净构建环境冻结 Server，验证 FastMCP 动态导入、包元数据、资源文件和 STDIO 协议，再接 GUI。不得从完整的个人 Anaconda 环境盲目收集全部包。

使用 PyInstaller onedir，将解释器和依赖收进 `.app`，最终用户不用安装 Python、pip 或 tunnel-client。构建依赖版本在实施阶段验证后锁定；本轮不下载或选装新依赖。

Tunnel runtime 的版本、来源 URL、SHA-256 和可再分发许可必须有清单，附上第三方许可证。当前目录的二进制只作为兼容性线索，不因为已存在就自动获得对外再分发资格；来源或许可不清晰时，正式发布停在待验证状态。

应用 bundle 中不写日志或配置，不在启动后修改已签名资源。测试含空格、中文、逗号的应用安装路径和项目路径。打包产物以构建目录输出，不将大型二进制提交进 Git。

## 验收标准

1. 一台未安装 Python/Conda 的 Apple Silicon Mac，解压安装包后能打开配置窗口。
2. 选目录、填写配置后能启动，并在 ChatGPT 读取所选项目的 README；首次连接步骤有明确引导。
3. 项目/安装路径带空格、中文和逗号可用；不访问根目录外文件，不改变已验证的只读工具合同。
4. 重复启动、切换项目、取消退出、正常退出和启动失败都不会产生孤儿进程或停止其他 Tunnel；强制退出 GUI 后，监护进程也应自动回收本应用连接。
5. 两个应用实例、其他 8080 服务或现有 Tunnel 并存时不会误判为自己的 ready；已有其他 Tunnel 客户端时按首版保守策略拒绝启动，并保留现有服务。
6. 配置和日志不出现明文落盘的 Key；系统钥匙串拒绝或锁定时有可理解的处理。
7. 原 25 项 Python 回归测试继续通过；冻结版 MCP 客户端测试验证工具名、分页和实际序列化响应低于 Tunnel 限制。
8. 正式包必须完成签名、公证和一台干净机器的下载安装验收；没有凭证时只交付明确标注的测试包。
9. 主窗口只展示核心选择、状态、主操作和设置入口；无副标题、功能介绍、常驻 helper text、默认日志或重复状态说明。设置表单也没有逐字段说明段落。
10. 浅色、深色及减少透明度设置下内容清晰；使用原生毛玻璃材质，非靠低对比小字制造极简；图标入口可被键盘和屏幕阅读器识别。
